EVALRIGHT - CLIENT LOGIN 2-STEP OTP AUTHENTICATION FLOW

This document explains the architecture, database changes, and API workflows implemented to support the two-step verification (OTP) layer for client user logins in EvalRight.

================================================================================
1. FLOW OVERVIEW
================================================================================
The client authentication now consists of two distinct stages:

STAGE 1: Username & Password Verification
1. The client enters their username and password in the login page.
2. The frontend sends a POST request to "/api/auth/login" with the credentials.
3. The backend validates the password hash:
   - If incorrect, returns a credential error.
   - If correct, instead of logging in directly, the backend:
     a. Generates a secure, 6-digit numeric OTP (e.g., 634005).
     b. Inserts the OTP into the "user_otps" table with a 5-minute expiration window.
     c. Triggers the Power Automate webhook asynchronously, passing the recipient's name, email, and the raw OTP.
     d. Responds with "otpRequired: true", the user ID, and their email.
4. The login screen automatically transitions to the "Two-Step Verification" screen.

STAGE 2: OTP Verification
1. The user retrieves the 6-digit OTP code sent to their registered email.
2. The user enters the code on the verification screen.
3. The frontend sends a POST request to "/api/auth/verify-otp" with the user ID and OTP.
4. The backend:
   - Queries the latest active, non-expired, non-verified OTP for that user.
   - Compares the codes.
   - Marks the database OTP record as verified (is_verified = true).
   - Retrieves and returns the complete authenticated user metadata.
5. The frontend logs the user in and redirects them to the home page.

================================================================================
3. DATABASE SCHEMA
================================================================================
The new "user_otps" table is configured as follows:
- id: UUID (Primary Key)
- user_id: UUID (Foreign Key referencing users.id ON DELETE CASCADE)
- otp_code: VARCHAR(6) (The numeric verification code)
- created_at: TIMESTAMP WITH TIME ZONE (Defaults to NOW())
- expires_at: TIMESTAMP WITH TIME ZONE (Validity deadline)
- is_verified: BOOLEAN (Defaults to FALSE)

An index is placed on "user_id" (idx_user_otps_user_id) for high performance.

URL Env: POWER_AUTOMATE_OTP_WEBHOOK_URL

  "otp": "634005"
